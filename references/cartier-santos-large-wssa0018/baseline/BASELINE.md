## Template for the next Santos variants (WSSA0071 blue, WSSA0062 green)

The prep, the step and the kit preset are measure / spec driven: a variant needs only its own photo, `-measure.json`, spec and job (no code change). Commands for a new SKU `<sku>` (lower case, letters and digits only; the Catalog 2 row gives size and photo URL) in `references/cartier-santos-large-<sku>/`:

```sh
# 1. photo saved as references/cartier-santos-large-<sku>/cartier-<sku>_original.jpg (never edited); write sources.md and REFERENCE_PLAN.md like this folder's
cp config/watches/cartier-santoslarge-wssa0018-measure.json config/watches/cartier-santoslarge-<sku>-measure.json   # then check / re-measure the per-photo values (below)
python3 -B -m pipeline.cartier_santoslarge_prep <sku>          # 2x copy, mask, trace, dial_photo.jpg, steel_photo.jpg
cp config/watches/cartier-santoslarge-wssa0018.json config/watches/cartier-santoslarge-<sku>.json            # sed every wssa0018 -> <sku>; model string; dial / hands / steel emission
sed 's/wssa0018/<sku>/g; s/WSSA0018/<SKU>/g' jobs/cartier-santoslarge-wssa0018.json > jobs/cartier-santoslarge-<sku>.json   # then fix the model / baseline strings
python3 -B -m pipeline.jobs validate jobs/cartier-santoslarge-<sku>.json && python3 -B -m pipeline.jobs run jobs/cartier-santoslarge-<sku>.json --force
cp outputs/jobs/cartier-santoslarge-<sku>/cartier-santoslarge-<sku>.glb models/watches/cartier-<sku>.glb
```

The kit preset `config/presets/watch_kit_white_front_cartier_santoslarge.json` is reused unchanged when the new photo has the same crop (pivot (375.0, 364.7), scale 7.6382 px/mm); the job already points to it. If the photo is cropped differently, copy the preset, set `scale_px_per_mm` to 2 x the new trace scale and keep the pivot at the frame centre.

Template (same for any Santos Large photo with this crop and case; verify by overlaying the render on the 2x photo translated by (+49.0, +69.6) for pivot (375.0, 364.7): silhouette differences below about 0.5 percent and a phase-correlation shift below 0.1 px mean the geometry holds): everything geometric in the measure JSON (`anchor`, `mask_tol`, `width_rows`, `horn`, `bezel.tl` outline quarter, `opening`, `dial_rect`, `screws`, `screw_r`, `guard_x`, `crown_rows`, `crown.profile_px`, `end_link_x`, `pieces_px`), the spec's geometry (`case` z values, bevels and `rays`, `crystal`, `dial.z`, `pose`, `bracelet` z / gap / bevel / backing, `crown`, `materials`, `hands.z` / thickness / ridge, the hands' `profile` lists), the step's part structure, steel emission 0.27, the mask method. Per watch (per photo): in the measure JSON the hand positions at the photographed time (`hour_tip`, `minute_tip`, `seconds_tip`, `seconds_tail`; the hub centre `pivot` and `hub_r` if the hub moved; measured with blue-minus-red half-max profiles in the rotated hand frame, the lengths and angles in the trace follow from the tips), and, only if a photo differs, any joint rows in `pieces_px`; in the spec `verified_mm.width` (39.8), the `model` string, the file paths, and emissions per dial colour: dial 0.34 for the white / silver dial (a blue or green dial is darker: tune from region means, the response is nonlinear, check both ways), hands 0.30, hands blue as projected from the photo. Check the mask on a gridded overlay at the horns, the crown guards and the strap edges (a dark dial does not change the mask; a photo with a different shadow may need `mask_tol` 5 to 6, never 7 or more, see Emission trials above).

Cartier-specific for the Santos (what differs from the Tank template):
- **Case**: no brancards or bars. The flank ring takes the photo silhouette between the horn rows (the four corner housings that continue into the bracelet end links, plus the crown guards at `guard_x`) up to the traced polished bezel outline; the bezel ring and the chamfer to the dial are sampled from the traced outline, the opening rectangle and the dial rectangle by rays from the pivot (every outline is star-shaped about the pivot). The pivot is not the dial centre; it costs nothing.
- **Bezel outline**: measured on gridded crops (top-left quarter from the top centre to the left centre) and mirrored about `cx` / `cy`; the S-curved notch at each corner is part of the quarter. Check the mirrored outline on the overlay at all four corners.
- **Bracelet**: one column (not outer / centre / outer); the first piece on each side is the end link between the horns with its own edges (`end_link_x`), the other pieces follow the silhouette edges, `z_pieces` lists the heights outward from the case; the backing runs 0.3 mm under the case.
- **Crown**: a lathe whose [radius, x] profile is measured in px in the measure JSON (`crown.profile_px`) and converted by the prep, so the spec only holds its axis height and segment count.
- **Frame convention**: a Lanczos 2x copy places photo pixel i at 2i + 0.5, so the registered photo is the 2x photo translated by (799.5 - 2 x pivot_x - 0.5, 799.5 - 2 x pivot_y - 0.5); using (800 - 2 x pivot) shows a 1 px shift in every phase-correlation test.
