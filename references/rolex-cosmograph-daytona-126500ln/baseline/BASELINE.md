## Template for the next Daytona variants (126503 champagne Rolesor, 126505 Everose chocolate, 126518LN yellow gold Oysterflex, 126508 yellow, 126508 green, 126519LN white gold Oysterflex, 126506 platinum ice blue, 126506A diamond version)

The step, prep and kit preset are generic (spec / measure / trace driven; variant-named for the Daytona 40 family and used READ-ONLY by key). Photos are in `references/rolex-cosmograph-daytona-<...>/rolex-<sku>*_original.png` (`ls references | grep daytona`). A variant needs only its own measure / spec / job JSON.

```sh
k=126503; ref=rolex-cosmograph-daytona-126503; photo=$(ls references/$ref/*_original.png)    # k = lowercase SKU (126508 yellow / green and 126506 / 126506A: k = 126508yellow, 126508green, 126506, 126506a; ref = the matching references folder)
python3 - "$k" "$photo" <<'PY'
import json, sys
k, photo = sys.argv[1], sys.argv[2]
m = json.load(open("config/watches/rolex-daytona40-126500ln-measure.json")); m["photo"] = photo
json.dump(m, open("config/watches/rolex-daytona40-%s-measure.json" % k, "w"), indent=1)
s = json.dumps(json.load(open("config/watches/rolex-daytona40-126500ln.json"))).replace("126500ln", k)
json.dump(json.loads(s), open("config/watches/rolex-daytona40-%s.json" % k, "w"), indent=1)
j = json.dumps(json.load(open("jobs/rolex-daytona40-126500ln.json"))).replace("rolex-daytona40-126500ln", "rolex-daytona40-" + k).replace("rolex-cosmograph-daytona-126500ln", "%s" % photo.split("/")[1])
json.dump(json.loads(j), open("jobs/rolex-daytona40-%s.json" % k, "w"), indent=1)
PY
# 1. re-measure what is listed below in config/watches/rolex-daytona40-$k-measure.json, 2. edit the new spec (model / note / bracelet or strap / emissions), 3. then
python3 -B -m pipeline.rolex_daytona40_prep $k            # trace, dial_photo.jpg, steel_photo.jpg
python3 -B -m pipeline.jobs validate jobs/rolex-daytona40-$k.json   # needs references/$ref/REFERENCE_PLAN.md
python3 -B -m pipeline.jobs run jobs/rolex-daytona40-$k.json --force
cp outputs/jobs/rolex-daytona40-$k/rolex-daytona40-$k.glb models/watches/<glb from rolex_map.json>
```

Edit the new spec's and job's `model` / `note` / `baseline` text by hand (the replace only swaps the SKU / ids; `sources.md` and `REFERENCE_PLAN.md` are per photo). The job's `kit_preset` stays `config/presets/watch_kit_white_front_rolex_daytona40.json` (read-only) while the new photo's pivot and scale agree within a pixel (check: the alpha mask of the new photo against `rolex-126500ln_original.png`; the watch spans x 511..1496, y 682..2513, leftmost case edge 510.75 at rows 1436..1440, horns 910 / 1990, case centre x 960.0; the hub screw at (960.25, 1424.6); if the new render differs, change `pivot` / `case_edge_left_x` in its measure and, only if the scale changes, copy the preset under a variant name).

**Same for every Daytona 40 variant (do not touch):** step, prep, kit preset, case heights and ramp, bezel geometry (rings and ellipses are identical on the same camera), crystal, crown / pusher geometry (re-check by overlay only), hub, sub-dial screws, pose and depth scale, hand heights `hands.z`.

**Per photo (re-measure, never trust these numbers):**
1. `measure.photo` (set by the snippet); then overlay the new `-trace.json` (hand outlines, `case_outline_mm`) on the photo at 3x: hour / minute / chronograph hand polygons (`hands.<name>.roi` poly in [s, w] along the hand from `hand_pivot_px`; each hand's angle changes with the photo's time, the shapes change between metals / dials: Everose and gold hands are bright against a light dial, so pick them on 8x rotated views like here, never by brightness), the three sub-dial needles (`polygons_px`, hub circle + needle, one `pivot_px` each) and `subdials` / `pushers` / `crown` if the overlay shows more than 2 px.
2. Emissions: dial (white 0.35; dark / coloured dials need their own value: a dark dial wants about 0.3 to 0.4, champagne / chocolate / ice blue check plate mean within ~1 %), steel 0.295 (gold, Everose and platinum steel maps may need +-0.02; check the bezel edge, lug and bracelet regions separately), `steel.bezel_emission` 0.21 (re-tune on the ceramic / bezel mean per photo: the bezel geometry is the same for every variant, a metal or differently coloured bezel only changes the emission), hands 0.34 (keep it close to the dial emission so the polygons blend into the dial).
3. Bracelet (`strap.bracelet` in the spec). **Oyster steel / Rolesor / gold (126503, 126505, 126508 x2, 126506, 126506A):** `columns: ["outer", "centre", "outer"]`, the layout and joint rows of this photo are expected to match (same camera, same bracelet): compare 4x strip crops first, keep the rows if they agree within 2 px (outer top 770.5 / bottom 2159, 2346, 2467; centre top 904.5, 875.5, 750 / bottom 2040.5, 2243, 2422, 2496; column lines in the spec note). **Oysterflex rubber strap (126518LN, 126519LN):** the strap is one black rubber piece per side: use `columns: ["strap"]` (a single column: left / right edges come straight from the alpha silhouette; `bounds_x_mm` is not read for one column; untested here, check the first render), `z_strap` (rubber height, about 2.8 to 3.0 with `z0` 0.6, `bevel` 0.15), `pieces_mm.strap.top / bottom` = one piece from the lug tip row to the strap end (or a few pieces where the Oysterflex shows its transverse flexible blades: read the dark lines on 4x crops, 22.4625 px/mm, pivot (960, 1425)); the metal lug caps are part of the case slab outline; the rubber's colour and gloss are the steel map (the black strap lowers the bracelet regions: re-tune steel emission with a bracelet-only check, since a rubber strap is darker than steel, and keep `steel_gap` for the backing). The brown / black strap pattern is texture. **Gold parts need no separate material** (see the Submariner Date two-tone build `references/rolex-submariner-date-126613ln/baseline/BASELINE.md`): the steel map carries the gold colour; two-tone Rolesor (126503) differs only by the bezel and centre-link colours in the photo.
4. `sources.md` row text and the dial / bezel / bracelet description in `REFERENCE_PLAN.md`; if the photo's colours differ from the tracker's variant, say so in the report. Check the number of pusher flutes and crown flutes only if the zoom crops show a mismatch (16 each here).
5. `bezel_ellipse` (ceramic outer edge, case flank) and `rings` come from edge scans about the hub; on the same camera they repeat within 2 px, so re-fit them only if the overlay of the ceramic edge disagrees. The first photo's bezel ring is 1.5 % flatter vertically than circular.
