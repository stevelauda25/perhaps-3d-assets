Soft: the dial print and indices are exactly as soft as the half-size photo (the crops come from the 1280 frame at half the native scale; the shipped textures are native 21.8 px/mm, so the real zoom in the app is 2x sharper than these crops); the render's pixel filter takes the thin black bezel rim lines and the brushed grain of the bracelet slightly softer than the INTER_AREA reference; bright steel highlights clip a little (render about 2 % lighter on the case top, flank and crown). No halos, dark gaps, stair-steps or misplaced hand edges were visible in the crops; the faint outlines in an amplified difference image around the print are 1 px registration / resampling residue.

## Template for the next Oyster Perpetual 41 variants (pistachio, sunburst blue, beige, lavender)

Photos are already in place (untracked): `references/rolex-oyster-perpetual-41-134300-<variant>/rolex-134300-<variant>_original.png` for `pistachio`, `sunburst-blue`, `beige`, `lavender` (1920 x 2857 RGBA; row positions 41..44, published GLBs `models/watches/rolex-134300-<variant>.glb`). Checked here against the green photo: the alpha masks of pistachio, sunburst blue and beige are IDENTICAL to the green one (0 differing pixels) and the bracelet / case pixels are identical too (lavender: mean abs grey difference 0.37 in the bracelet), i.e. one camera, one case, one bracelet: the whole geometry holds for every colour. Only the dial map, the dial emission and the dial-related photo pixels differ. Reuse the step, prep and kit preset READ-ONLY.

```sh
v=pistachio; key=134300-$v          # variants: pistachio | sunburst-blue | beige | lavender  (name = "${v//-/ }")
sed "s/134300-green/$key/g" config/watches/rolex-oysterperpetual41-134300-green-measure.json > config/watches/rolex-oysterperpetual41-$key-measure.json
sed "s/134300-green/$key/g; s/green dial/${v//-/ } dial/" config/watches/rolex-oysterperpetual41-134300-green.json > config/watches/rolex-oysterperpetual41-$key.json
sed "s/134300-green/$key/g; s/134300 green/134300 ${v//-/ }/; s/green dial/${v//-/ } dial/" jobs/rolex-oysterperpetual41-134300-green.json > jobs/rolex-oysterperpetual41-$key.json
python3 -B -m pipeline.rolex_oysterperpetual41_prep $key          # trace, dial_photo.jpg, steel_photo.jpg (native, no scaling)
python3 -B -m pipeline.jobs validate jobs/rolex-oysterperpetual41-$key.json   # needs references/<ref>/REFERENCE_PLAN.md (write it from the green one) before it validates
python3 -B -m pipeline.jobs run jobs/rolex-oysterperpetual41-$key.json --force
cp outputs/jobs/rolex-oysterperpetual41-$key/rolex-oysterperpetual41-$key.glb models/watches/rolex-$key.glb
python3 -B -m pipeline.glb_audit models/watches/rolex-$key.glb /tmp/x.md
```

(the job's `references` list and `kit_preset` already point at the shared preset; write `sources.md`, `REFERENCE_PLAN.md` and `baseline/` into the variant's reference folder, copy `baseline_spec.json` / `baseline_job.json` from your spec / job, and run `python3 -B -m pipeline.zoom_check <baseline dir>`).

**Template (keep as is, same for every colour):** `pipeline/steps/watch_rolex_oysterperpetual41.py`, `pipeline/rolex_oysterperpetual41_prep.py`, `config/presets/watch_kit_white_front_rolex_oysterperpetual41.json` (pivot and scale are the same: verify with an overlay of the variant's first render, silhouette difference below ~60/255), the whole `measure` file (pivot (961, 1424), case flank x 512 / centre 959, rings, crown, tip rows, bracelet joint rows) and, in the spec, the whole geometry: case (body_z 7.2, tip_z 3.3, ramp, bevel 0.35, tips 23.0 / 25.0), bezel profile (z0 7.0, dome 8.55..9.2), crystal, dial z, crown (20 flutes, z 4.4), bracelet (columns outer / centre / outer, bounds, pieces_mm, gap 0.06, z levels), pose, heights, materials, steel emission 0.29, hands emission 0.36.

**Per dial colour (re-check, never trust the green numbers):**
1. `measure.photo` (done by the sed) and the spec/job ids.
2. Spec `dial.emission`: green = 0.31 (plate 1.004 : photo; the response is weak and nonlinear: 0.35 -> 0.30 moved the plate 1.020 -> 1.000). Light dials (pistachio, beige, lavender) will clip: start at 0.28..0.30 for a mid-light dial, lower for white-ish ones, and tune so the dial plate mean lands within about 2 % (run a region-mean script as described in "State" above: dial disc r < 165 px in the 1280 frame about the ring centre, hands excluded if you can) while the print and indices still read; sunburst blue has a radial gradient, check centre and rim separately.
3. Hands: if the time shown differs from about 10:09:30, re-measure hour / minute / seconds angles and tips (perpendicular edge scans, the numbers are in the measure note and trace) and the spec `hands.profile` lists (half widths). The photographed hands stay in the dial map either way; the 3D hands only need to cover them (a wider-than-photo hand is invisible in the front view, since every layer shows the same projected photo). Check the hands by overlay of the first render before measuring anything.
4. `sources.md` row text (Catalog 2 colour) and the dial description in `REFERENCE_PLAN.md`; if the photo's dial colour is not the tracker's variant, say so in the report.
5. Steel emission stays 0.29 (the steel pixels are identical), so the steel region ratios should reproduce the table above (bracelet top 1.007, bottom 0.993, bezel 1.011).

Rolex plan (other families share parts): the Oyster bracelet (outer / centre / outer) and the plain fluted crown are in this step and spec; a Submariner / GMT / Sea-Dweller needs a rotating-bezel variant of the bezel lathe (copy this step: a black insert ring as in `watch_tudor_bb58.py`) and a Jubilee / President bracelet only needs a different `strap.bracelet.columns` / `bounds_x_mm` / `pieces_mm` (the column builder takes any column list).
