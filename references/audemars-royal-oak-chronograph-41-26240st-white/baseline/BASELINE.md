## Template for the next Royal Oak Chronograph variants (green row 93)

The green Royal Oak Chronograph 41 (catalog row 93, same SKU 26240ST, photo `standup-994`) follows with these files: the prep, step and kit preset are generic; the variant needs only new measure / spec / job JSON. The variant key is `26240st-green` (the SKU repeats, so the key carries the colour, also in the GLB name). The lead has to download the green photo as `references/audemars-royal-oak-chronograph-41-26240st-green/audemars-26240st-green_original.png` and `..._1200x1626.png` first (the folder already exists for the white one's sibling rows).

```sh
key=26240st-green                                                         # variant key; the white one is 26240st-white
ref=references/audemars-royal-oak-chronograph-41-$key                     # holds audemars-$key_original.png and audemars-$key_1200x1626.png
cp config/watches/audemars-royaloakchrono41-26240st-white-measure.json config/watches/audemars-royaloakchrono41-$key-measure.json   # then MEASURE every value again on the new photo (list below)
python3 -B -m pipeline.audemars_royaloakchrono41_prep $key                # 2x copy, trace, dial_photo.jpg, steel_photo.jpg (MODEL constants stay: same ref prefix, name, 41 mm)
cp config/watches/audemars-royaloakchrono41-26240st-white.json config/watches/audemars-royaloakchrono41-$key.json   # change trace, dial_map, steel_map, hands (profile / offsets as measured), dial emission, bracelet pieces
sed 's/26240st-white/'$key'/g' jobs/audemars-royaloakchrono41-26240st-white.json > jobs/audemars-royaloakchrono41-$key.json   # id / output / spec / trace / glb / reference strings; step and kit preset stay (edit the model / baseline text)
cp $ref/../audemars-royal-oak-chronograph-41-26240st-white/REFERENCE_PLAN.md $ref/REFERENCE_PLAN.md          # edit the measured values and the catalog row
python3 -B -m pipeline.jobs validate jobs/audemars-royaloakchrono41-$key.json && python3 -B -m pipeline.jobs run jobs/audemars-royaloakchrono41-$key.json --force
cp outputs/jobs/audemars-royaloakchrono41-$key/audemars-royaloakchrono41-$key.glb models/watches/audemars-$key.glb
```

The kit preset `config/presets/watch_kit_white_front_audemars_royaloakchrono41.json` is shared while the new photo has the same scale (6.9268 px/mm) and pivot (599.4, 792.9); if the prep prints another `scale_px_per_mm`, copy the preset and set `scale_px_per_mm` = 2 x that and keep `center_px` [640, 640] (1280 frame), and point the job's kit stage at the copy.

**Template (keep as is):** the step `pipeline/steps/watch_audemars_royaloakchrono41.py` (case slab from the silhouette, octagon bezel ring by rays with chamfer, eight screws, dial lathe with the photo map, crystal, hands from profile lists with `offset_mm`, hexagonal crown and pusher parts from `trace.crowns` with `ring_shift_mm`, chain-of-links bracelet), the prep, the kit lighting / camera, materials (`steel_gap`, `lume`, `crystal`), pose and depth scale, heights (`case` body_z 5.2 / tip_z 2.9 / bezel_z 7.2 / chamfer_z 6.7 / chamfer_mm 0.3 / bezel_bevel 0.2, `crystal`, `dial` z 5.6 / ring_z 5.9, `hands.z`, `crown.z` 4.0, bracelet z_full 2.9, lift 0.15, bevel 0.15, backing_material steel_photo), the octagon (same case: flats 457.5 / 741.5 / 651.5 / 936.0 px if the photo has the same framing), steel emission 0.31, hands emission 0.43, the comparison-script conventions (continuous px, the 2x pivot moved to the frame centre).

**Per variant (re-measure on the photo, never copy):**
- Photo: AP serves a 400 x 542 PNG; the working source is the `&wid=1200&hei=1626` rendition. The two photos of the SAME model may differ by a pixel or two in pivot and flats; do not assume the white values.
- `pivot`: hub centre (rotational-symmetry search of the grey values around (599, 793), then check the hub ring on a 24x tile); `anchor.left_x / right_x`: outer edges of the polished left / right bezel bands on the row of the pivot (the printed `scale_px_per_mm` must be near 6.93; a different value means a misread edge); `octagon` top / bottom from the polished band outer edge on the column of the pivot.
- `opening_circle_px`: radial scans of the bezel / chapter-ring edge, robust circle fit (here r 110.4 about (599.9, 792.3), rms 0.26 px); `dial_flat_r_px` / `ring_in_r_px` (96 / 97 here); `screws_px`: convex-hull centres of the white hexagon heads (symmetric about x = 600; mind the upper right one, a stray feature moved its automatic fit) and `screw_r_px`.
- `crowns`: the crown base on the notch wall and the two pushers by their silhouette extent along the axis (63 / 117 degrees; hex R 18.2 px, cap r 10.5 px, `ring_shift_px` from the cap-centre offset); `crown_replace` lines for the three right-side parts (upper pusher rows, crown seat, lower pusher rows; end each line one row after the part's last silhouette row, otherwise a spike remains).
- Hands: the green dial uses the same steel hands; re-measure angles and lengths (the photo may show another time; the hour hand's `offset_px` and the seconds tail angle change with it), half-width profiles from rotated 14x crops. A green dial has less contrast against the hands: the dark inlay edges still separate them.
- Bracelet: joint gap rows (dark segments of the brightness profile along x = 580, top and bottom), `pieces_mm` = the links between them in |y| mm, `backing_mm`, lug tips (`tip_top` + `tip_bottom` a multiple of 0.25 mm).
- Emissions: region ratios with the list above (dial plate / bright / chapter ring, bezel face, lug top / bottom, bracelet top / bottom, crown, pushers, hands, whole watch); the green dial is the one thing that differs in colour: re-tune the dial emission by two runs (a dark green dial needs less than the white one: the response is nonlinear).
