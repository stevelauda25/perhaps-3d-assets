This is the **first Moonwatch** and sets the **Omega Moonwatch template** (see the last section). Approval is the designer's; this file is not a similarity score.

## Template for the next Moonwatch variants (Silver Snoopy 310.32.42.50.02.001 nylon strap, Calibre 321 311.30.40.30.01.001)

The prep, step and kit preset are generic: a variant needs its own measure / spec / job JSON and a copy of the prep with another MODEL name. Nothing of this build is to be edited, copy it.

```sh
sku=<lower-case sku, letters and digits only>   # Silver Snoopy: 31032425002001 (310.32.42.50.02.001), Calibre 321: 31130403001001 (311.30.40.30.01.001)
ref=references/omega-speedmaster-<slug>-$sku     # folder that already holds omega-$sku_original.png (Silver Snoopy / Calibre 321 folders exist)
name=omega-moonwatch-<variant>                   # e.g. omega-moonwatch-snoopy, omega-moonwatch-cal321 (keeps output folders apart)
cp pipeline/omega_moonwatch_prep.py pipeline/omega_${name#omega-}_prep.py     # edit MODEL (ref slug, name), the default sku; nothing else for a bracelet watch
cp config/watches/omega-moonwatch-31030425001001-measure.json config/watches/$name-$sku-measure.json   # MEASURE every value again on the new photo (list below)
python3 -B -m pipeline.<new prep module> $sku    # 2x copy, trace, dial_photo.jpg, steel_photo.jpg
cp config/watches/omega-moonwatch-31030425001001.json config/watches/$name-$sku.json   # set model, trace, dial_map, steel_map, verified_mm, all hand / sub-dial / pusher / crown / strap numbers, emissions
cp jobs/omega-moonwatch-31030425001001.json jobs/$name-$sku.json                      # replace id / output / spec / trace / glb strings; the step stays watch_omega_moonwatch
cp config/presets/watch_kit_white_front_omega_moonwatch.json config/presets/watch_kit_white_front_$name.json   # scale = 2 x px_per_mm, center_px = 2 x pivot of the 2x frame (2048 holds the watch)
python3 -B -m pipeline.jobs validate jobs/$name-$sku.json && python3 -B -m pipeline.jobs run jobs/$name-$sku.json --force
cp outputs/jobs/$name-$sku/$name-$sku.glb models/watches/omega-$sku.glb
```

(The step is `pipeline/steps/watch_omega_moonwatch.py`; no code change is needed for a steel bracelet. The scratch helper that turned the pixel numbers into the spec is not part of the repo: write the spec numbers directly, mm = (px - pivot) / scale, y flipped.)

**Template (keep as is):** the step (case from the silhouette with `right_override_px` for crown / pusher rows, one-ring tachymeter bezel lathe, domed crystal, dial lathe with the photo map, profile hands with lume polygons, sub-dial hand polygons and hub discs, crown with domed cap, `pushers.items` with their own origins / angles, five-column bracelet with `bounds_x_mm` / `pieces_mm` / `edge_from`), the kit lighting and camera (only scale and centre change), materials (`steel_gap`, `lume`, `crystal`), pose and depth scale 0.35, heights (`case`, `bezel`, `crystal`, `dial`, `hands.z`, `crown.z`, pusher `z`), steel emission 0.30, hands emission 0.415, dial emission 0.325 for a black dial (a silver / white dial is lighter: check both ways, the response is nonlinear), the cmp / regions conventions (frame = 2x photo frame; compare with a region table of the scratch folder).

**Per watch (re-measure on the photo, never copy):**
- Photo: 1024 x 1024 RGBA PNG, upright render with a slight tilt / yaw, crown at 3, pushers at about 2 and 4 o'clock. Positions are continuous px (pixel i spans [i, i+1]). The bracelet runs off the image (the prep clamps the steel-map crop); a strap may end inside the image.
- Scale: `scale_px_per_mm` in the measure file. For the 42 mm Moonwatch cases (the Silver Snoopy is 42 mm too, the camera is probably the same: check the lug rows 163.7 / 768.5 and the case width) 12.7; the Calibre 321 is 39.7 mm with another lug to lug: measure case width / lug to lug / lug width again (a smaller watch in the same frame gets a different px/mm); the Catalog row size is the case diameter (`verified_mm`).
- Pivot: least-squares point of the hour, minute and chrono seconds axes (edge-midpoint line fits in rotated strips, thr 100 on the black dial; with a silver dial threshold the dark hands instead); rings: bezel outer circle by 50 percent crossings on rays (dark ring to steel), inner chamfer / dial rings by radial profiles; `ring_centre_mm` = ring centre minus pivot.
- Hands: `hands.profile` (symmetric half widths along the axis, tail first), `hands.lume` strips / diamond, `hands.polygons` + `hands.discs` for the sub-dial hands and hubs (hub circles by boundary ray fits, batons by coverage widths). The 3D hands only add relief, colour comes from the projection.
- Crown / pushers: crown box (`crown.x0, x1, y0, y1, fluted_to_x`) from axis-aligned views (`rot` crops) and `right_override_px` rows (silhouette rows replaced by the straight flank / guard line); each pusher from an axis-aligned view: origin (point on the crown side), angle (slope of its top / bottom edges), end distance, button start, radius.
- Bracelet (steel version): `columns` (outer, narrow, centre, narrow, outer), `bounds_x_mm` from brightness-valley centroids per row band, `pieces_mm[column][top|bottom]` from vertical brightness scans per column (outer and narrow share rows, the centre staggers), the first piece of the outer column carries the lug inner x limits, `edge_from`, `tip_top` / `tip_bottom` (multiples of 0.25 mm).
- **Nylon / fabric strap (Silver Snoopy 310.32.42.50.02.001; what the strap variant needs):** there is no bracelet column layout, so use the rubber build of `pipeline/steps/watch_omega_diver300m.py` (`strap.kind` "rubber": columns of flat pieces with `bounds_x_mm`, `pieces_mm`, `groove`, `lift`, `edge_from`, material `strap_photo` = the same projected photo with its own emission / roughness 0.8 / specular 0). That step does not have the chronograph parts (pushers, sub-dial polygons and discs, `ring_centre_mm` items): the cleanest way is to copy `pipeline/steps/watch_omega_moonwatch.py` to `watch_omega_moonwatch_nylon.py` and add the three things of the Diver step to it: the `strap_photo` material block, the `rubber` branch of the strap loop (`kind` assert, lift over the case ramp, `edge_from` clamp) and `bracelet_links` material `strap_photo`. For a plain NATO-style nylon strap use ONE column (`columns` ["strap"], no `bounds_x_mm` joints) or two to three columns for the woven stripe borders, with the strap's loops / keepers as separate short pieces at the rows measured from the photo (a keeper = a short piece slightly wider than the strap, y range from a brightness scan); the weave, stripes, stitching and the printed pattern stay flat photo texture (`strap_photo`); the strap passes between the lug bars, so the end piece between the lugs takes the lug inner x limits like the first bracelet link. The strap colour (blue / grey nylon) is the projected photo: tune `strap.rubber.emission` per colour (dark about 0.31, light up to 0.5, check the region ratios both ways) and say plainly that the weave and stitching are flat. The Silver Snoopy dial is silver / white with a blue sub-dial and a Snoopy print in the photo (dial map as is; dial emission higher than 0.325, light dials about 0.45 to 0.55), blue hands and sub-dial hands to re-measure, no bezel difference except the colour (photo).
- **Calibre 321 (311.30.40.30.01.001, 39.7 mm, steel bracelet, step as is):** expect a different layout (the catalogue photo decides: lug shape, guards, bracelet columns and joint rows may differ): re-measure everything; the crown cap and pusher dimensions differ; ring radii differ, hand shapes need new profiles.
