This is the **first Patek Philippe** and sets the **Aquanaut template** (see the last section; the 5168G green and blue, catalog rows 102 and 104, 42.2 mm white gold, follow it). Approval is the designer's; this file is not a similarity score.

## Template for the next Aquanaut variants (5168G green row 102, blue row 104)

The Aquanaut 5168G (42.2 mm, white gold, green / blue embossed dial, composite rubber strap, same SKU in two rows) follows with these files: the prep, step and kit lighting are generic; the variant needs its own measure / spec / job JSON and a kit preset copy with the new scale. Variant keys `5168g-green` and `5168g-blue` (the SKU repeats, so the key carries the colour, also in the GLB name `models/watches/patek-5168g-green.glb`). The photos are already in `references/patek-aquanaut-5168g-green/patek-5168g-green_original.png` and `references/patek-aquanaut-5168g-blue/patek-5168g-blue_original.png` (1920 x 2691 RGBA, same studio render as this one).

```sh
key=5168g-green                                                           # or 5168g-blue
ref=references/patek-aquanaut-$key                                        # holds patek-$key_original.png
cp config/watches/patek-aquanaut40-5167a001-measure.json config/watches/patek-aquanaut40-$key-measure.json   # then MEASURE every value again on the new photo (list below); case_mm = 42.2
python3 -B -m pipeline.patek_aquanaut40_prep $key $key                    # trace, dial_photo.jpg, steel_photo.jpg; prints scale_px_per_mm (expect about 30: the 5168G photos are the same render size, the watch is 1369 x 2170 px incl. the crown for green, 1365 x 2162 for blue, so the kit frame of 1280 px at half scale still holds it with margin)
cp config/watches/patek-aquanaut40-5167a001.json config/watches/patek-aquanaut40-$key.json    # change model, trace / dial_map / steel_map paths (sed 5167a001 -> $key), verified_mm.diameter 42.2, tips, hands, strap pieces, emissions
cp jobs/patek-aquanaut40-5167a001.json jobs/patek-aquanaut40-$key.json                         # sed 5167a001 -> $key in id / output / spec / glb; references; step and kit stage stay
cp config/presets/watch_kit_white_front_patek_aquanaut40.json config/presets/watch_kit_white_front_patek_aquanaut40_$key.json   # set cameras.front_ortho.ortho.scale_px_per_mm = printed scale / 2; point the job's kit stage at it
python3 -B -m pipeline.jobs validate jobs/patek-aquanaut40-$key.json && python3 -B -m pipeline.jobs run jobs/patek-aquanaut40-$key.json --force
cp outputs/jobs/patek-aquanaut40-$key/patek-aquanaut40-$key.glb models/watches/patek-$key.glb
```

Compare as `cmp.py` did: half-size photo (`cv2.resize(.., 0.5, INTER_AREA)`) translated by (640 - 0.5 px0, 640 - 0.5 py0) onto white, against `cmp-front.png`; region masks from the trace (window polygon, superellipse, strap rows).

**Template (keep as is):** the step `pipeline/steps/watch_patek_aquanaut40.py` (case slab from the silhouette, superellipse bezel ring cut back to the silhouette, scanned window and chamfer, polygon dial / crystal, hands from profile / lume lists with the two hub discs, lathe crown from `trace.crowns`, one-piece rubber strap with per-side emission and backing), the prep (all scanning and map writing), the kit lighting / camera, materials (`steel_gap`, `lume`, `crystal`), pose and depth scale, heights (`case` body_z 6.6 / tip_z 3.4 / bezel_z 8.9 / chamfer_z 8.2 / bezel_bevel 0.2, `crystal`, `dial` z 7.0, `hands.z` 7.4 / 7.65 / 7.9, `crown.z` 5.0), hands emission 0.43, strap roughness 0.8 / gap 0.06 / `z_side` 3.3 / lift / bevels, the comparison conventions (half native scale, 1280 frame, pivot at the centre).

**Per variant (re-measure on the photo, never copy):**
- Size: `case_mm` in the measure file = 42.2 (Catalog 2). The scale is (pivot x - left flank) / (case_mm / 2): check the printed `scale_px_per_mm` against the lug-to-lug and strap width (strap 22 mm at the 5168G lugs, flank rows where the flank is vertical: re-read `anchor.rows`, here 1330..1400). Every spec value in mm (tip_top / tip_bottom, ramp_from_y, strap `pieces_mm` start 18.5 and ends 29.9 / 39.9, hand and lume profiles, hub radii) is the measured px divided by the trace scale: re-derive them from the new pixels, never reuse the 40 mm numbers.
- `pivot`: the screw at the centre of the white hub disc (5x crop of the hub), check with the hour / minute centre lines (edge fits in rows rotated about the pivot).
- `bezel_outer`: superellipse from the top / bottom polished edge rows at the centre column (here 763.5 / 1936.5), the flank, and 2 off-centre columns (exponent from them, here 2.25); `aperture`: `bright_thr` (the white-gold face is brighter than steel: check the scan overlay, the red line must sit on the first brushed pixel), `min_run_px` (longer than the indices, shorter than the bezel face), `chamfer_px`.
- `crown_replace`, `crowns`: crown rows (1281..1447 here), axis y, radius, base under the case, `profile_px` (radius, axial) from the silhouette rows; `strap_inner_px`: lug rows, bezel rows (strap-visible limits) and the inner walls (median of the dark-to-bright threshold scans).
- Hands: angle (edge fits: rotate the image about the pivot by the hand angle, threshold at about 112 for the steel frame and 205 for the lume, line-fit both edges until the mid slope is 0), half-width / lume profiles, tip, seconds tail. The 5168G has white-gold hands with a lume inlay of the same pattern: the profile shape is the template, the numbers are not.
- Emissions: region ratios with the list above (dial plate / bright / dark, bezel face, strap top / bottom, lugs, crown, whole watch); the green and blue dials and the white gold are the things that differ in colour: re-tune dial and steel emission by two runs each (the dial response is nonlinear and nearly flat for steel); strap emission top and bottom separately.
