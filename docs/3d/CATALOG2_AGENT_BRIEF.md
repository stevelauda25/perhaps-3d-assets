# Brief for building one Catalog 2 watch GLB (front relief)

Repo root `/Users/admin/Documents/perhaps-3d-assets`; run all commands from it. You build ONE watch asset; a sibling agent builds another at the same time in the same checkout, so touch ONLY the files this brief allows. Your task header (the prompt that sent you here) gives: the row, the photo, the names to use, and whether you are creating a NEW MODEL template or following an existing one (FOLLOWER).

## Goal
A front-relief GLB whose front view matches the catalogue product photo as exactly as possible, 1:1 in shape, position, colour and texture, following the baseline the designer established (Tudor Royal 36 -0101, called "perfect") and the finished templates. The photo is already downloaded: do NOT download anything else, no network use. The designer approves, not you; never claim photorealism; report residual differences honestly.

## The recipe (copy it, never reinvent it)
Steel parts (case, bezel, crown, bracelet/strap) carry the reference photo projected straight from the front (`steel_photo.jpg`, planar UV from x, y) plus emission; the dial is a photo map (`dial_photo.jpg`; the photographed hands stay in it, so a hand may hide a numeral exactly as in the photo); 3D hands sit over the photographed ones; the case outline is the alpha silhouette; bracelet rows/pieces are placed at joints measured from the photo (top and bottom separately: pixel-grid crops at 3-6x and brightness-gradient scans); emissions are tuned so region means land within a few percent of the photo (steel ~0.28-0.33; dial per colour, dark ~0.30-0.4, light up to ~0.55; the response is nonlinear, check both ways). The comparison render must be in the same pixel frame as the photo around the pivot (the kit preset defines the camera; use a frame large enough for the whole watch).

## NEW MODEL mode
Read the closest finished sibling, measure EVERYTHING from the photo (bezel, crown, hands, dial layout, lume, bracelet/strap layout, case shape, chronograph pushers/sub-dials if any), and make model-specific copies: `pipeline/steps/watch_<name>.py` (copy of the closest step, adapted, spec-driven and generic so later variants only need new spec/measure JSON), a prep copy `pipeline/<name>_prep.py` ONLY if the closest prep does not fit, your own kit preset `config/presets/watch_kit_white_front_<name>.json`, `config/watches/<name>-<sku>{,-measure,-trace}.json`, `jobs/<name>-<sku>.json`. Spec `verified_mm` = the case diameter (or listed size). BASELINE.md gets an extra "Template for the next <model> variants" section (exact commands, template vs per-dial values). At most 5 correction passes.

## FOLLOWER mode
Reuse the named template's step/prep/kit preset READ-ONLY (they are spec/registry driven), re-verify registration by overlay (pivot/scale usually match within a few px; silhouette differences below ~60/255 mean the template geometry holds) and re-measure only per-photo things: hand tips/tails/widths/lume/colour, hub, windows, crown if different, strap or bracelet pieces if different, dial emission (colour dependent), steel emission. Copy the sibling spec/job/measure to your own files with new ids/paths. A prep/step copy only if a code change is unavoidable (variant-named). At most 4 correction passes.

## Matching to the photo (hard requirement: 1:1)
After the first build compare `cmp-front.png` with the photo in the same frame (side-by-side). Measure region mean-luminance ratios render:photo (dial, dial outer ring, bezel, bracelet/strap top and bottom, case top/bottom, crown, hands/numerals/indices) and correct concrete differences (positions, shapes, joints, brightness). Earlier builds ended within a few percent per region; dark dial areas typically stay ~5% light. Stop early when only the photo's drop shadow/background or unmeasurable detail remains.

## Designer requirements for every asset (from the designer's note)
The app: users can only pinch-zoom, never rotate; mobile; photoreal product quality.
1. **Real 3D geometry, layered**: every asset is an actual mesh built from layered parts (case, bezel, crystal, dial plate, hands at different heights, crown/pushers, bracelet/strap), never a textured plane. Report meshes/triangles/materials (`python3 -B -m pipeline.glb_audit models/watches/<your>.glb /tmp/x.md`).
2. **1:1 front fidelity, small details first**: dial markings, typography, hands, textures and materials must match the photo at zoom, not only in region means. After your last pass run `python3 -B -m pipeline.zoom_check <your baseline dir>` (3x crops of reference and render), fix visible artifacts a change in your files can fix (misplaced hand edges, halos, wrong print, stair-steps, dark gaps, wrong colours), and list what remains under "Zoom check" in BASELINE.md (what is sharp, what is soft and why).
3. **Front-locked**: optimise for the front view; ignore side views.
4. **Lighting vs the app's 3D environment**: the photo's lighting is baked into the textures and reproduced with emission, so the asset does not depend on a studio. Keep specular low and avoid strong environment reflections on photo-projected parts; add no extra baked shadows beyond the photo. State which parts are emissive and at what strengths (they are in your spec).
5. **Mobile performance**: working targets file <= 2.5 MB, <= 60,000 triangles, textures <= 2048 px on the long side (JPEG, quality tuned). Remove triangles the front view cannot show; avoid dense lathes where 96-192 segments are not visible at the shipped size; never trade visible quality for size.
